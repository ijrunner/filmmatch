## 1. 主流程（3 分钟 · 2 节点）

1. 达芬奇新建时间线，放一段素材（或一张静帧），建 **2 个节点**：
   `① 校正 → ② 单节点 DCTL（匹配 + look + 质感）`
2. **② 加载 `FM_match_yrgb_fl06.dctl`**：用 **Color 页 → OpenFX / 特效库 → ResolveFX Color → DCTL**，加载后在**检查器**里点选该文件。
   - **这是 R14 待验证项 ① 的正步骤**：预期「全层 DCTL 经 ResolveFX Color → DCTL 加载成功、检查器出现滑杆」。若这一步失败（报 `wrong argument int p_Width` 之类），说明加载途径被走错或产品回归——记入回执。
   - **不要**用「节点右键 → LUT → DCTL」加载**全层**文件：LUT 路径只吃**逐像素签名**（见步骤 3 的正路径）。
   - **换文件后必须重启达芬奇**：`Update Lists` 不会重载已应用的 DCTL（会继续用旧编译产物）。
3. **逐像素签名版走 LUT 路径（R14 待验证项 ② 的正步骤，约半分钟）**：把准备 2 里导出的「只导出色彩层」DCTL，用**节点右键 → LUT → DCTL** 加载到 ① 或临时节点上。预期：**加载成功、画面色彩变化生效**（无参数面板属正常）。这一步验证色彩层-only 的逐像素签名确实可走 LUT 路径——也就是「全层走 ResolveFX、色彩层可走 LUT」的完整分野。
4. **确认 ② 生效**：检查器里出现滑杆（含匹配段共 **63** 项，其中 `匹配-*` 11 个）、画面叠加质感层（光晕/颗粒/暗角）。试 `FM_MATCH_ON` 关掉匹配段、试改 10 个匹配系数（slope/offset/power/sat），确认响应。
5. **数据范围校验（R17，约 1 分钟，已并入主流程）**：
   1. 达芬奇项目设置/素材属性里确认素材是 **Video/Legal** 还是 **Full/Data**（拿不准就先按 Legal 试，偏色方向会给出答案）；
   2. 工作台 ⑤ 保存/导出区把「数据范围」切到 **Video/Legal**（HUD 右下角「范围」同步显示 Legal），点「下载 .cube」导入达芬奇节点 LUT，同帧对比网页预览：
      - 整体偏色/发灰消失、黑位对得上 → 范围校验通过；
      - 仍有整体偏色 → 把开关切回 Full/Data 再导一次对比（两种都试一次即可定位），把结论记进回执；
      - `.cube` 头部有 `COMMENT data-range: ...` 行声明本次导出的范围，可核对。
6. **HSL 承载口径（一行确认）**：配方若带 **HSL 8 色相**（R18 起 XMP 导入/进阶面板可产生），该维度**只进网页预览与 `.cube`/LUT 路径，DCTL 面板不承载**（生成页有明示行）。走查对比时：带 HSL 的配方请在 **LUT/`.cube` 路径**对比色彩走向，DCTL 滑杆里找不到 HSL 属预期，不是丢层。
7. **同帧对比**：网页工作台停在同一个配方截图；达芬奇同帧截图。并排看：
   - 光晕的亮通阈值（DCTL 作用于源图，网页作用于已 look 图 → 极端参数下晕色差异最大）
   - 颗粒（R9 后 DCTL 应为**逐帧变化**，不再是静止的）
   - 片门抖动（R9 新增，默认关；开了看是否有位移且不过头）
   - 整体反差/饱和度走向是否一致
8. **记录**：把「哪一步不成立 / 差异有多大 / 哪个更接近」写下来（截图 + 一句话即可），按 §3 模板填回执。

## 2. 进阶（想看「匹配」与「look + 质感」分层时 · 4 节点）

只有需要把匹配与 look 分开调、或要单独对比统一 LUT 时，才走这条：

1. 建 **4 个节点**：`① 校正 → ② CDL（匹配）→ ③ DCTL（look+质感）→ ④ LUT（风格层，二选一）`。
2. **先只开 ①②**：确认 CDL 生效、画面朝参考方向靠。CDL 用达芬奇自带 Color 面板的 CDL，或跑 zip 里的 `_mount.py`（Studio 版）。
3. **再开 ③**：③ 加载 `FM_yrgb_fl06.dctl` / `FM_rcm_fl05.dctl`（同样用 **ResolveFX DCTL 插件 + 检查器选文件**，换文件后重启达芬奇）。确认面板滑杆（无匹配段 **52** 项）与质感层生效，逐个拖几个关键滑杆确认响应。
4. **③ 与 ④ 二选一**：DCTL 与 LUT 都承载 look，同时开会重复叠加——记录哪个更接近网页预览。

## 4. 注意事项

- **DCTL 加载途径分野（v2 主流程的正步骤即验这个）**：带质感层（邻域采样）或参数面板的 `.dctl` 一律用 **Color 页 → OpenFX/特效库 → ResolveFX Color → DCTL** 加载，再在检查器里选文件；**LUT 路径（节点右键 → LUT → DCTL）只适用于逐像素签名**，即只含色彩层、无质感层的 DCTL（生成页「只导出色彩层」会产出这一版，没有参数面板）。
- **每次换 `.dctl` 文件后必须重启达芬奇**：`Update Lists` 不会重载已应用的 DCTL（会继续用旧编译产物）。
- **HSL 维度只进网页与 .cube/LUT 路径，DCTL 面板不承载**（生成页有明示行；配方带 HSL 时生成器会显式警告）。
- 实机验证环境是 **Windows + CUDA(NVRTC)**；OpenCL 在该机器不可用（画面全黑），一律按 CUDA 验。
- 像素量按 **1080p** 固化在 DCTL 里：2160p 时间线要把半径/颗粒/色散参数按比例 **×2**（生成器 warnings 与 zip 内《首次上手清单》都写了）。
- 闪退时别慌：把 `davinci/dctl-samples/bisect/` 的 `60/61/62` 依次试一遍，判读表在 `bisect/README-测试顺序.md`；报错原文直接贴回来即可定位。
- 免费版 DCTL 可用性仍未知（此前只在 Studio 验过）：若免费版能加载 DCTL，质感层就不需要手录；不能加载则走 zip 内《免费版手录说明.md》。
